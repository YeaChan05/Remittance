### 통합 테스트 (Integration Test)

멀티 모듈 환경에서 각 컴포넌트 간의 상호작용과 전체 비즈니스 흐름을 검증하기 위해 통합 테스트를 수행한다

#### 1. 테스트 원칙

- **실제 환경과 유사하게**: 가능한 한 실제 데이터베이스(MySQL)와 연동하여 테스트를 수행한다 이를 위해 `Testcontainers`를 활용한다
- **격리된 테스트**: 각 테스트 메서드 실행 전후로 데이터베이스 상태를 초기화하여 테스트 간 간섭을 방지한다
- **명확한 시나리오**: 단순 API 호출 검증을 넘어, 동시성 테스트나 복잡한 비즈니스 시나리오(이체 -> 알림 전달 등)를 검증한다

#### 2. @SpringBootTest 활용

전체 애플리케이션 컨텍스트를 로드하여 테스트를 수행한다 `aggregate` 모듈의 `AggregateApplication`을 설정 클래스로 지정하여 모든 도메인 로직을 통합 검증한다

```kotlin
@SpringBootTest(
    classes = [AggregateApplication::class],
    properties = ["transfer.outbox.publisher.enabled=false"] // 필요 시 특정 스케줄러 비활성화
)
class ConcurrentTransferNotificationSpecs {
    @Autowired
    lateinit var transferCreateUseCase: TransferCreateUseCase
    // ... 기타 의존성 주입
}
```

#### 3. 동시성 및 비동기 검증

이체와 같이 정밀한 수치 계산과 동시성 제어가 필요한 경우, `ExecutorService`와 `CountDownLatch`를 사용하여 실제 경합 상황을 재현하고 검증한다

- `eventually` 유틸리티: 비동기로 처리되는 결과(Outbox 이벤트 처리, 알림 발송 등)를 검증하기 위해 일정 시간 동안 반복 확인하는 패턴을 사용한다

#### 4. 데이터 초기화

테스트 간 독립성을 보장하기 위해 `EntityManager`를 사용하여 모든 테이블의 데이터를 삭제하는 `reset()` 메서드를 `@BeforeEach`에서 호출한다

#### 5. 테스트용 Props 정의

실제 요청 DTO 대신 테스트 코드 내부에 `TestMemberProps`, `TestAccountProps` 등 인터페이스를 구현한 데이터 클래스를 정의하여 도메인 객체 생성에 필요한 필드들을 유연하게 구성한다
